# Источники данных

Использовать первый доступный способ. Все команды только читающие.

## Комментарии к MR

1. Пользователь вставил текст или указал файл - использовать его как есть. Внутри песочницы это обычно файлы из `.mr-review/`, которые пользователь выгружает на хосте командой `sh devtools/mr-comments.sh <номер>` (`devtools/mr-comments.sh`): `mr-<номер>-discussions.json` (треды с `id`, предпочтительный источник) и `mr-<номер>-comments.txt` (текст).
2. GitLab, установлен и авторизован `glab` (вне песочницы):
   ```bash
   glab mr view <номер> --comments | cat
   ```
   `| cat` отключает pager. Если версия `glab` поддерживает машинно-читаемый вывод (`glab mr view --help`, флаг `--output json` или `-F json`), предпочесть его: разбор надёжнее.
3. GitHub: `gh pr view <номер> --comments`.
4. Ничего не доступно - попросить пользователя вставить комментарии. Не искать токен и не ходить в API напрямую.

## Описание MR

Название и описание MR (цель, ссылка на задачу, перечень изменений) берутся из того же источника, что и комментарии: `mr-<номер>-comments.txt` (`glab mr view --comments` печатает их перед комментариями) или вывод `glab mr view <номер> | cat` / `gh pr view <номер>`. В `discussions.json` описания нет. Если описание получить нельзя или оно пустое, сказать об этом в выжимке и сравнение с diff не проводить.

## Diff

1. Есть `.mr-review/mr-<номер>.diff` (на хосте: `sh devtools/mr-comments.sh <номер> --diff`) - использовать его: UI показывает фрагменты кода для замечаний именно по этому файлу. Контекст читать из рабочей копии, если ветка извлечена; иначе - по правилу шага 4 `Review.md` (новые файлы из `+`-строк, номера строк из хунков).
2. Локальная ветка: определить базу и посмотреть изменения.
   ```bash
   git log --oneline <база>..HEAD
   git diff <база>...HEAD
   ```
   База по умолчанию - `develop`; если пользователь назвал другую, использовать её.
3. Чужой MR без локальной ветки: `glab mr diff <номер>` или `gh pr diff <номер>`.
4. Пользователь вставил diff - использовать его, а контекст читать из рабочей копии, если файлы совпадают.

## Ограничения среды

- Внутри Docker/devcontainer `glab` не установлен и токена нет намеренно (`.devcontainer/README.md`, «Комментарии MR для агента»). Это не ошибка скилла: если `.mr-review/` пуст, попросить пользователя выполнить `sh devtools/mr-comments.sh <номер>` на хосте или вставить текст.
- Не предлагать пользователю выдать агенту токен API и не пытаться установить `glab` в контейнере.
