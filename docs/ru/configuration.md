# Конфигурация

[English](../configuration.md) | Русский

Файл `.revdeck.yml` (или `.revdeck.yaml`) в корне репозитория. Схема проверяется через zod;
неизвестное поле — ошибка с путём.

```yaml
version: 1
provider:
  type: auto            # auto | gitlab | github
  host: gitlab.example.com
  project: group/project
  base: develop
output:
  language: auto        # auto | ru | en — язык замечаний и ответов
review:
  agents: 3
  roles: [correctness, architecture, tests]
rules:
  sources: [AGENTS.md]
  map:
    - match: ["src/**", "lib/**"]
      docs: ["docs/Architecture.md", "docs/Styleguide.md#Базовый стиль"]
      note: "прикладной код"
  ignore: ["**/generated/**"]
checks:
  - id: lint
    name: ESLint
    argv: [npm, run, lint]
    when: ["src/**"]
    consent: true
    timeoutMs: 300000
publish:
  requireApproval: true
  maxComments: 50
```

## Личные настройки: `.revdeck.local.yml`

`revdeck` читает `.revdeck.local.yml` (или `.revdeck.local.yaml`) рядом с базовым конфигом. В нём можно
переопределить роли, проверки, язык вывода или provider, не меняя общий файл. `init` добавляет оба
локальных имени в `.gitignore`.

Правила слияния:

- объекты сливаются рекурсивно;
- массивы и скаляры из локального файла заменяют базовое значение;
- `review.readOnly: true` из базового файла нельзя отключить локально (эффективное значение — OR);
- локальный файл может быть единственным, но для команды лучше иметь базовый `.revdeck.yml`;
- ошибки YAML/схемы в локальном файле показываются, а не игнорируются.

```yaml
# .revdeck.local.yml — не коммитить
review:
  agents: 2
  roles: [correctness, tests]
output:
  language: ru
```

## provider

| Поле | По умолчанию | Смысл |
|---|---|---|
| `type` | `auto` | `auto` — по git remote; иначе явная платформа |
| `host` | из remote | хост без схемы |
| `project` | из remote | GitLab `group/project`, GitHub `owner/repo` |
| `base` | `develop`/`main` | база для локального diff |

Явные аргументы CLI (`--platform`, `--project`, `--host`) важнее конфига, конфиг важнее git remote.
Так подмена `.git/config` не перенаправит ревью на чужой проект.

## output

- `language: auto` — замечания и ответы пишутся на языке описания MR и обсуждений; если текста нет,
  используется английский. `ru`/`en` фиксируют язык явно.
- Язык правил и документов от этого не зависит: агент читает их как есть и цитирует в оригинале.
- Это язык **результата ревью**, а не интерфейса CLI/UI. Интерфейс переключается `--lang ru|en`,
  `REVDECK_LANG` или переключателем в UI.
- `revdeck init --lang en` выбирает английский skill и пишет `REVDECK_LANG` в MCP-конфиг.

## review

Ревью можно разделить между независимыми агентами. Демон хранит итог; запуск агентов выполняет harness
(субагенты Claude Code, workflow DSH или другой оркестратор).

```yaml
review:
  agents: 3
  roles: [correctness, architecture, tests]
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `agents` | `3` | число независимых ревьюеров, 1–8 |
| `roles` | correctness, architecture, tests | роли ревьюеров; короткий список повторяется до `agents` |

Доступные роли:

| Роль | Фокус | Criteria.md |
|---|---|---|
| `correctness` | логика, граничные случаи, ошибки, async и состояние | §6, §10 |
| `architecture` | слои, ответственность, связность, прецеденты, ADR | §3–§5, §7 |
| `tests` | покрытие, assertions, пропущенные случаи, нестабильность | §8 |
| `security` | авторизация, валидация, секреты, инъекции, shell | §10 |
| `performance` | сложность, N+1, аллокации, блокирующие операции | §10 |
| `compatibility` | публичный API, миграции, конфиги, обратная совместимость | §6, §7 |
| `docs` | документация, конфиги, CHANGELOG и AI-инструкции | §9 |
| `concurrency` | гонки, блокировки, идемпотентность, retries, отмена | §10 |
| `ux` | состояния UI, доступность, ошибки, узкие экраны | §9, §10 |
| `data` | схемы, миграции, хранение | §3, §10 |
| `api` | публичные контракты, версионирование, совместимость клиентов | §6, §7 |
| `dependencies` | версии, лицензии, supply chain | §3, §10 |
| `observability` | логи, метрики, трейсы, диагностика | §9, §10 |
| `build` | CI, сборка, упаковка, воспроизводимость | §8, §9 |
| `privacy` | PII, персональные данные, логи и утечки | §9, §10 |
| `general` | полное ревью по всем разделам | §1–§12 |

Кастомные роли задаются в `review.customRoles`; `roles` может ссылаться на встроенные роли или на
эти ключи:

```yaml
review:
  roles: [correctness, accessibility]
  customRoles:
    accessibility:
      title: "Доступность"
      description: "Клавиатурная навигация, ARIA, фокус и контраст."
      criteria: ["9", "10"]
      focus: "a11y и клавиатура"
      instructions: |
        Сообщай только о проблемах доступности; не повторяй общие замечания по архитектуре.
```

Кастомный id не может переопределить встроенную роль. `review.readOnly: true` запрещает изменения и
публикацию для этого ревью (UI показывает баннер, демон отклоняет мутации).

Несколько MR можно открыть одной командой `revdeck open 345 344 556` (или массивом в `revdeck_open`);
для каждого ревью запускается отдельная группа, замечания разных MR не смешиваются.

`revdeck context <N> --role <роль> --shard i/N` отдаёт контекст только с файлами шарда (и тредами по
этим файлам) и напоминает не писать findings. MCP-инструмент принимает те же `role` и `shard`.
Лид-агент собирает JSON воркеров, дедуплицирует по `file:line:title` и только потом вызывает
`revdeck_set_summary` / `revdeck_draft_findings`.

## rules

- `sources` — точные пути к документам (можно с `#секцией`), не glob-шаблоны. Для выбора документов по
  изменённым путям используйте `map.match`. Документы по умолчанию, если ни одна строка `map` не
  подошла. Пусто — автообнаружение
  (`AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `docs/ARCHITECTURE.md`, `docs/Architecture.md`,
  `docs/STYLEGUIDE.md`, `docs/Styleguide.md`, `docs/CONTRIBUTING.md`).
- `map` — список правил: `match` (glob или массив glob) и `docs` (массив селекторов). Несколько
  совпавших строк объединяются.
- `ignore` — glob-исключения: файл не попадает в анализ правил.
- `maxDocumentBytes` — лимит на документ в байтах. `0` (по умолчанию) — без лимита; жёсткий предел
  чтения одного файла — 16 МБ.
- `maxTotalBytes` — лимит на собранный контекст правил и отрендеренный текст. `0` (по умолчанию) —
  без лимита.

Загрузка всех правил увеличивает промпт: расход токенов, время ответа и риск упереться в контекстное
окно модели. Финальный контекст агента всё равно можно ограничить опцией CLI/MCP `max_bytes`. Если
гайды очень большие, задайте меньший `maxTotalBytes` (например, `327680`) или привяжите только нужные
секции.

### Откуда берутся предупреждения

Блок **Предупреждения** в UI появляется, когда в `review.errors` попадают сообщения загрузки конфига:

- `.revdeck.yml not found: rules come from auto-discovered documents` — в корне репозитория нет
  `.revdeck.yml`/`.revdeck.yaml`. `revdeck init` создаёт его; без конфига берутся значения по умолчанию,
  а документы правил ищутся автоматически.
- `no rule documents found: the review will rely on the code only` — после загрузки конфига
  `rules.sources` и `rules.map` пусты, и ни одного автообнаруженного файла нет. Список:
  `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `docs/ARCHITECTURE.md`, `docs/Architecture.md`,
  `docs/STYLEGUIDE.md`, `docs/Styleguide.md`, `docs/CONTRIBUTING.md`.

Чтобы убрать оба предупреждения, добавьте `.revdeck.yml` и перечислите существующие документы либо
создайте один из автообнаруживаемых файлов:

```yaml
version: 1
rules:
  sources:
    - AGENTS.md
    - docs/Architecture.md
```

Если заданы `rules.sources`/`rules.map`, автообнаружение отключается; отсутствующий явный документ
даст отдельное предупреждение. Пустой `sources: []` оставляет автообнаружение включённым.

### Группы изменений

```yaml
review:
  groups:
    - id: auth
      title: "Авторизация"
      match: ["src/auth/**", "src/security/**"]
```

Явные группы применяются первыми; остальные файлы группируются по типу (docs, tests, config, styles,
generated) и верхнему модулю. Группы видны в «Обзоре» и в контексте агента.

### Скан секретов

По умолчанию выключен:

```yaml
review:
  secrets:
    enabled: true
    scan: diff          # diff | files | both
    includeTests: false
    allowlist: ["test/fixtures/**", "rule:generic-secret"]
```

Сканер ищет ключи AWS/GitHub/GitLab/Stripe/OpenAI, private keys и generic secret assignments.
Возвращается только замаскированный preview; сырые значения не сохраняются в ревью и не уходят
агенту. `revdeck scan <N>` возвращает тот же список.

### История версий

```yaml
review:
  history:
    enabled: true
    keep: 20
```

Каждое обновление с изменившимся head/diff сохраняет версию (head/base SHA, diff hash, счётчики и
снимок ревью). `revdeck versions <N>` показывает список; в «Обзоре» есть таймлайн. Хранится не больше
`keep` версий.

### Селекторы документов

| Селектор | Что берётся |
|---|---|
| `docs/Architecture.md` | весь документ |
| `docs/Styleguide.md#Базовый стиль` | секция заголовка (уровень и ниже, до заголовка того же уровня) |
| `docs/File.md#L10-L25` | диапазон строк |
| `docs/File.md#10-25` | то же |

Заголовок нормализуется: регистр, пробелы и пунктуация не важны, `#Слои и зависимости` и
`#layers` — разные секции, а `#Слои-и-зависимости` и `#Слои и зависимости` — одна. Если секция не
найдена, revdeck пишет предупреждение и не подставляет весь документ.

### Glob

`*` — в пределах одного сегмента, `**` — любая глубина, `?` — один символ, `{a,b}` — альтернатива.
Примеры: `src/**/*.ts`, `docs/{guides,adr}/**`, `**/*.test.ts`.

## checks

Проверки — argv-массивы, без shell-строк. Это важно: конфиг лежит в репозитории, и строка shell
позволила бы исполнить произвольный код при ревью.

| Поле | Смысл |
|---|---|
| `id` | стабильный идентификатор |
| `name` | отображаемое имя |
| `argv` | команда и аргументы; первым идёт исполняемый файл |
| `when` | glob-пути: запускать, только если diff их затронул; пусто — всегда |
| `consent` | требует явного подтверждения (по умолчанию `true`) |
| `timeoutMs` | таймаут (по умолчанию 300 000) |

Запуск: `revdeck checks <N> --run --yes` или кнопка **Запустить подходящие** на вкладке «Правила» с
подтверждением. В read-only проверки отключены. MCP-инструмент только показывает план.

## publish

- `requireApproval` — оставлен для совместимости; approval требуется всегда, когда публикует не
  интерактивный процесс.
- `maxComments` — максимум комментариев за один план (1–200).

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `REVDECK_STATE_DIR` | каталог состояния (по умолчанию `~/.local/state/revdeck`) |
| `REVDECK_RUNTIME_DIR` | каталог сокета (по умолчанию `$XDG_RUNTIME_DIR/revdeck`) |
| `REVDECK_URL` + `REVDECK_TOKEN` | подключение к демону по HTTP (контейнер/проброс порта) |
| `REVDECK_DEV_CONTAINER=1` | не запускать локальный демон, а подсказать про демон хоста |
| `REVDECK_UI_HOST` | хост для `revdeck ui` из контейнера (например, `host.docker.internal`) |
| `REVDECK_ROOT` | корень проекта для MCP-сервера |
| `REVDECK_LANG` | язык CLI/MCP/демона: `ru` или `en` (по умолчанию системная локаль) |
| `REVDECK_GLAB` | абсолютный путь к `glab`, если его нет в PATH демона |
| `REVDECK_GH` | абсолютный путь к `gh`, если его нет в PATH демона |

## Валидация

`revdeck config --json` показывает эффективный конфиг, найденный путь и предупреждения.
`revdeck rules --explain src/app.ts` показывает, какие документы и секции выбраны для файла.
